# MCP (Model Context Protocol) 整合 TODO 與設計筆記

本文件概述了在 Paper Burner Chatbot 中整合 MCP 功能的計劃，重點關注客戶端能力以及未來對本地後端助手的考量。

## 1. 階段一：純前端 MCP 客戶端 (基於瀏覽器)

**目標：** 使聊天機器人能夠充當 MCP 客戶端，發現並呼叫那些透過 Web 友好協議暴露的 MCP 伺服器工具。

**主要功能點與 TODO：**

-   **[ ] `mcp-client.js` (新檔案，位於 `js/chatbot/mcp/`):
    -   **[ ] 連線管理:**
        -   實現 `McpClient.connect(serverUrl)`：建立和管理與 MCP 伺服器的連線。初期主要針對暴露 HTTP/SSE 端點的伺服器。
        -   允許使用者在設定中配置 MCP 伺服器 URL。
    -   **[ ] 工具發現 (`listTools`):
        -   實現 `McpClient.listTools()`：根據 MCP 規範向連線的 MCP 伺服器傳送 `listTools` 請求。
        -   解析響應，獲取可用工具列表、描述和輸入模式 (input schema)。
        -   儲存/快取當前伺服器的可用工具。
    -   **[ ] 工具呼叫 (`callTool`):
        -   實現 `McpClient.callTool(toolName, toolArgs)`：構造並向 MCP 伺服器傳送 `callTool` 請求。
        -   處理同步的（HTTP 請求/響應模式）工具呼叫。
        -   解析工具的響應並返回結果 (例如 `result.content`)。
    -   **[ ] 針對流式工具的 SSE 支援 (如果適用):
        -   調研並實現對透過伺服器傳送事件 (SSE) 提供流式輸出的工具的支援。
        -   使用 `EventSource` API 連線到 MCP 工具提供的 SSE 端點。
        -   處理傳入事件並逐步流式傳輸工具輸出，類似於當前處理 LLM 流式響應的方式。
    -   **[ ] 錯誤處理與穩健性:**
        -   實現針對連線失敗、無效伺服器響應、工具呼叫錯誤等的穩健錯誤處理機制。
-   **[ ] 與 Agents 整合 (`js/chatbot/agents/`):
    -   **[ ] `LongTextAgent` 和 `RetrievalAgent` 利用 `McpClient`:
        -   Agents 可以發現並呼叫相關的 MCP 工具（例如，專門的文件分塊工具、透過 MCP 暴露的向量搜尋工具）來增強其處理能力。
-   **[ ] UI 注意事項 (更新 `js/chatbot/ui/` 模組):
    -   **[ ] 允許使用者在設定中新增/管理 MCP 伺服器端點。
    -   **[ ] 考慮在介面上展示可用的 MCP 工具，或允許使用者根據上下文觸發它們。

**認證機制:**

-   **[ ] 初期重點關注無需認證或基於 API 金鑰的 MCP 伺服器（前提是金鑰可以被安全管理或由使用者為特定伺服器提供）。
-   **[ ] TODO (未來):**調研並實現對 OAuth 2.0 授權碼模式（如果合適，也可以是客戶端憑證模式）的支援，以應對需要此類認證的 MCP 伺服器。這可能涉及到將使用者重定向到認證伺服器並處理回撥。

## 2. 階段二：本地後端助手/伺服器 (未來增強)

**目標：** 引入一個輕量級的本地後端應用程式，以克服瀏覽器限制並解鎖高階功能。這將保持核心聊天機器人在瀏覽器中的純粹可用性，本地伺服器作為一個可選的增強功能。

**主要功能點與 TODO (由本地後端伺服器處理)：**

-   **[ ] 高階資料持久化與恢復:
    -   **[ ] 提供 API 端點，供前端將關鍵資料（聊天記錄、思維導圖、設定）儲存到本地檔案系統（例如 JSON 檔案、SQLite）。
    -   **[ ] 提供 API 端點，供前端在 `localStorage` 被清除或不可用時請求資料恢復。
    -   **[ ] (可選) 與使用者選擇的雲端儲存同步（需要仔細的安全和認證設計）。
-   **[ ] 本地 OCR 與後端轉發的 OCR:
    -   **[ ] 提供 API 端點以接收前端的影象資料。
    -   **[ ] 整合本地 OCR 引擎（例如，如果後端是 Python，則透過 Python 環境整合 PP-OCR）。
    -   **[ ] 安全儲存線上 OCR 服務（例如 Doc2X）的 API 金鑰，並充當前端對這些服務請求的代理。
-   **[ ] 增強的 MCP 功能:
    -   **[ ] MCP 伺服器的 Stdio 橋接:
        -   充當橋樑，執行使用 stdio 傳輸的本地 MCP 伺服器（例如 Python 腳本）並與之通訊。
        -   透過本地後端，將這些基於 stdio 的 MCP 伺服器透過 HTTP/SSE 暴露給前端。
    -   **[ ] 前端作為 MCP 伺服器 (透過本地後端代理):
        -   本地後端在特定埠監聽來自外部客戶端（包括其他瀏覽器擴充）的 MCP 請求。
        -   將這些 MCP 請求轉發給 Paper Burner 前端（例如，透過前端和本地後端之間建立的 WebSockets 或其他持久連線）。
        -   前端（例如，一個新的 `js/chatbot/mcp/frontend-mcp-server-logic.js`）透過呼叫其內部模組 (`LongTextAgent`, `ChatbotCore`, `toc_logic.js`) 來處理請求。
        -   透過本地後端將響應返回給外部 MCP 客戶端。
        -   這使得瀏覽器擴充可以透過本地後端進行通訊，利用其 MCP 代理能力。

**本地後端技術堆疊 (考量)：**

-   Python (Flask/FastAPI) - 適合 AI/ML 任務，生態成熟。
-   Node.js (Express) - JavaScript 生態系統一致性。
-   Go / Rust - 高效能，單二進位制檔案部署。

**關於階段劃分的說明：**
階段一允許聊天機器人立即消費任何可透過 Web 訪問的 MCP 伺服器提供的工具。階段二透過利用本地處理能力並充當更通用的 MCP 中心，顯著擴充了功能，但這需要使用者執行一個獨立的本地應用程式。
